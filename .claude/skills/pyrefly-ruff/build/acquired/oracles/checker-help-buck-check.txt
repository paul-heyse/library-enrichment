Entry point for Buck integration

Usage: pyrefly buck-check [OPTIONS] <INPUT_PATH>

Arguments:
  <INPUT_PATH>
          Path to input JSON manifest

Options:
  -j, --threads <THREADS>
          Number of threads to use for parallelization. Setting the value to 1 implies sequential
          execution without any parallelism. Setting the value to 0 means to pick the number of
          threads automatically using default heuristics
          
          [env: PYREFLY_THREADS=]
          [default: 0]

  -o, --output <FILE>
          Path to output JSON file containing Pyrefly type check results

      --color <COLOR>
          Control whether colored output is used
          
          [env: PYREFLY_COLOR=]
          [default: auto]
          [possible values: auto, always, never]

      --min-severity <MIN_SEVERITY>
          Minimum severity level for errors to be displayed. Errors below this severity will not be
          shown. Defaults to "error"
          
          [possible values: ignore, info, warn, error]

      --report-pysa <OUTPUT_DIR>
          Generate Pysa-compatible output files for each module

  -v, --verbose
          Enable verbose logging
          
          [env: PYREFLY_VERBOSE=]

      --report-pysa-format <REPORT_PYSA_FORMAT>
          Format for pysa report output (json or capnp)
          
          [default: capnp]
          [possible values: capnp, json]

      --progress-bar <PROGRESS_BAR>
          Set the progress bar style. `interactive` shows a visual progress bar. `simple` prints
          periodic log-style progress messages (suitable for piping or non-interactive use). `no`
          (default) disables progress reporting entirely

          Possible values:
          - interactive: Show an interactive progress bar (default)
          - simple:      Show simple log-style progress messages, suitable for non-interactive use
          - no:          Disable progress reporting entirely

      --check-dependencies
          Also check dependency files, which are normally only used for import resolution

      --skip-dependency-modules <REGEX>
          When checking dependencies (`--check-dependencies`), skip type-checking dependency modules
          whose module name matches any of these regexes. May be passed multiple times. Has no
          effect without `--check-dependencies`

  -h, --help
          Print help (see a summary with '-h')
