## Findings

Four defects surfaced. None affects correctness of evidence that was returned; all four
affect what a caller can reach or how a failure is described.

**F1: `inspect_symbol` with default aspects fails on high-fanout symbols.**
`datafusion::prelude::SessionContext` at `depth="signature"` (`req_4f7e884b6cba45b984ce8ec410c9e6c9`),
`datafusion::dataframe::DataFrame` (`req_57de13a2fc3847b3b4a82c515fbe8de2`),
`datafusion::prelude::ParquetReadOptions` (`req_ae413331cb224f87a39a2fa8ed70c778`) and
`datafusion_expr::Expr` in its own crate (`req_012bb236a3a64961bd21070051f92e9c`) all return
`status: "error"`, code `BUDGET_EXCEEDED`, message
`snapshot query failed: query failed: Resources exhausted: relationship alternatives exceed inspection bound`,
`retryable: true`. Passing `aspects=["signature"]` or `["signature","documentation"]`
succeeds on every one of them, so the bound is in the `relationships` aspect, which the default
aspect set includes. A method (`DataFrame::window`) and a five-variant enum
(`RegisterFunction`) succeed with defaults. Expected per the wire contract: a `partial` answer
with bounded relationships and a truncation note, not an error. Workaround for agents: name
aspects explicitly and request `relationships` separately.

**F2: an unknown `job_id` is reported as a service-state I/O failure.**
`job_control` on `job_00000000000000000000000000000000` (`req_09e52e3aa6a34820bed09783169d3731`)
returns `ARTIFACT_UNAVAILABLE` with message
`service state could not be read: No such file or directory (os error 2)`, `retryable: true`,
and the next action `Check that the service data directory is readable; see library-enrichmentd status`.
The error is typed, so the shape passes, but the message attributes a caller mistake to the
data directory and marks it retryable.

**F3: a comparison scope with no evidence on either side reports zero changes silently.**
`compare_releases` for `datafusion` 54.1.0 to 55.1.0 with `scopes=["release_notes","docs"]`
(`req_27d9ee7a21ed429dbb6c9198ba0e84cf`, stored answer `art_8417920faeafcc5f3408a8a6cd35b1e8`)
returns 24 docs-scope changes, `coverage.missing: []` and no limitation about release notes,
although both resolves had reported `missing: ["release_notes"]`. A caller could read that as
"no release-note changes". The docs scope itself is correct and carries `readme_section`
evidence with before and after text.

**F4: revision mode fails on any repository archive that contains a symlink.**
`resolve_library` with `mode="revision"`, `repository=https://github.com/apache/datafusion`,
`revision=7d3835c71f30cbd3c3ae4041732267f1f453097a` (the 55.1.0 tag), with and without
`package_subdir="datafusion/core"` (`req_63e9ac32e7fc49d68825118d8cf6f5cb` via job
`job_b83215bfb6ab492488990af9693eb307`; `req_aed198b185374714823896736eedd8a5`), fails with
`EXTRACTION_FAILED`: `entry apache-datafusion-7d3835c/CLAUDE.md is a symlink, which is never extracted`.
Refusing to extract symlinks is the right policy, but failing the whole acquisition instead of
skipping the entry and recording a gap makes revision mode unusable for this monorepo and any
other that carries a symlink. G10.3 could not run because no revision context exists.

## Correct behaviour that is not a failure

These results are by design on a static-only host with no qualified producer image, and the
campaign treats them as passes.

- `POLICY_DENIED` from `verify_usage` (both modes) and from `inspect_symbol` with an execution
  profile. Each names the missing operator action; none silently compiled or ran anything on
  the host, and `verification.unresolved` counted two attempts.
- `partial` from `search_evidence` with `kinds=["source"]`: source text is not lexically
  indexed and the limitation says where source is reached instead.
- `partial` from every resolve served from retained evidence, with typed `not_attempted` gaps
  for `examples` and `release_notes` and the limitation that the mutable registry was not
  consulted.
- `partial` from `library_overview` and `search_evidence` whenever `examples` or
  `release_notes` are not indexed for the crate; the missing kinds are always listed.
- `BUDGET_EXCEEDED` carrying `data.result_artifact_id`: the bounded-output protocol, not a
  failure. Following the cursor reassembled every stored answer.
- `VERSION_NOT_FOUND`, `INVALID_CURSOR`, `UNSUPPORTED_FORMAT` and `ARTIFACT_UNAVAILABLE` on
  the designed-refusal inputs.
- `UPSTREAM_UNAVAILABLE` with `retryable: true` from every tool while the daemon was stopped.

## Observations

Non-defects worth knowing when driving the service from an agent.

- O1: fragment hits are not folded across re-export paths; one doc fragment for
  `SessionState::window_functions` came back three times under three module paths. Symbol hits
  fold correctly.
- O2: the `verify_usage` denial names the profile but not the concrete setup commands that
  `service_status` names.
- O3: struct namespaces in `library_overview` list no children; methods and fields are counted
  in `definitions_by_kind` but reached only through search.
- O4: a rustdoc rendering change (`Infallible` versus `never`) surfaces as a potentially
  breaking API change; the toolchain confounder is disclosed but not attributed.
- O5: identical evidence is `ok` with `coverage.missing` on first acquisition and `partial`
  with typed gaps when served from retention.
- O6: with eight concurrent resolves in flight most exceed the two-second inline wait and go
  `pending`; a later `cache_ok` resolve returns the retained answer, with the identifiers in
  the envelope even when the body is stored.
- O7: a source excerpt's line range over-approximates the item; the `RegisterFunction` excerpt
